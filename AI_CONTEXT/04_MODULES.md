## Bulk and webhooks (4.5.0)

- Bulk-job methods are duplicated per package (`ShortLinkClient`, `QRCodeClient`) as thin wrappers over core's `LinkBulkJobApi(http, kind)`; there is no separate bulk package.
- `createMany` splits rows into chunks, sends each with `Idempotency-Key: <key>-<chunk>` and retries a chunk only on a network error / 5xx (`isRetryableBulkError`), so a resend never double-creates.
- `@posty5/webhooks` is not exposed through MCP (api BW-D12). The verifier needs Node `crypto`.
- Request/response shapes mirror `api/AI_CONTEXT/modules/link-tools-service/link-bulk-job.md` and `webhook-endpoint.md`.

## Editing rule

Start changes in the owning module. Move code to shared/core only after more than one feature genuinely owns the behavior. Update this file and [MODULE_INDEX.json](MODULE_INDEX.json) when ownership changes.

## QR design engine (4.7.0)

- `@posty5/qr-design` is pure: no fetch, no DOM, no canvas. The logo arrives as a `data:` URI from the caller. Rasterising (PNG via sharp, PDF via pdfkit) belongs to the api.
- Determinism has three sources: 3-decimal `fmt()`, FNV-hashed def ids, and frame text as outlines from `src/fonts/glyphs.data.ts`. That file is generated by `npm run build:glyphs`; never edit it by hand.
- Arabic is shaped in-house (`src/text/`). opentype.js cannot apply Noto Sans Arabic's GSUB.
- `qrcode-generator` is bundled (`tsup noExternal`). UTF-8 is encoded by the package, not by the library's global `stringToBytes`.
- Tests are the `qr-design` Jest project. There is no live API and no root `setup.ts`. The suites are:
  - golden hashes in `__tests__/golden.json`, shared by the Node and jsdom suites (`npm run golden:update`);
  - a ZXing decode of every fixture.
